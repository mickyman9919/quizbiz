# ⚡ QuizBlitz — เกมควิซเรียลไทม์แบบ Kahoot

เว็บแอปเกมตอบคำถามแบบเรียลไทม์ ผู้ดูแลตั้งคำถามได้เอง เปิดห้องพร้อม QR code ให้ผู้เล่นสแกนด้วยมือถือแล้วแข่งตอบพร้อมกัน

## ฟีเจอร์
- **หน้า Admin** (`/admin`) สร้าง/แก้ไข/ทำสำเนา/ลบแบบทดสอบ
  - คำถาม 2–4 ตัวเลือก หรือแบบ ถูก/ผิด, เลือกคำตอบที่ถูกได้มากกว่า 1 ข้อ
  - ตั้ง **เวลาแต่ละข้อ** (5–240 วินาที), คะแนนปกติ / สองเท่า / ไม่คิดคะแนน, ใส่ลิงก์รูปประกอบได้
  - นำเข้า/ส่งออกแบบทดสอบเป็นไฟล์ JSON
- **จอโฮสต์** (`/host`) สำหรับเปิดบนโปรเจกเตอร์
  - ห้องรอพร้อม **QR code** + Game PIN 6 หลัก, เห็นผู้เล่นเข้ามาแบบเรียลไทม์, ล็อกห้อง, คลิกชื่อเพื่อนำผู้เล่นออก
  - นับถอยหลัง, จำนวนคนที่ตอบแล้ว, ปิดคำถามอัตโนมัติเมื่อทุกคนตอบครบ
  - **สรุปทุกข้อ**: กราฟจำนวนคนตอบแต่ละตัวเลือก, % ตอบถูก, เวลาเฉลี่ย แล้วตามด้วยตารางคะแนน Top 10 (คะแนนที่ได้เพิ่ม, อันดับขึ้น/ลง, 🔥 ตอบถูกติดกัน)
  - **สรุปตอนจบ**: โพเดียม 3 อันดับ, อันดับทุกคน, สถิติรายข้อ, ดาวน์โหลด CSV
- **หน้าผู้เล่น** (`/play`) ออกแบบสำหรับมือถือ
  - ตั้งชื่อเอง, เลือกตัวละคร 46 แบบ + สีพื้น 12 สี หรือกด 🎲 สุ่ม
  - ปุ่มตอบสี/สัญลักษณ์ใหญ่, เห็นผลถูก/ผิด คะแนนที่ได้ และอันดับของตัวเองทุกข้อ
  - รีเฟรชหน้าหรือเน็ตหลุดแล้วกลับเข้าห้องเดิมได้ คะแนนไม่หาย

## วิธีคิดคะแนน
- ตอบถูก: ได้ 500–1,000 คะแนนตามความเร็ว (ตอบทันทีได้เต็ม, ตอบตอนหมดเวลาได้ครึ่ง)
- ข้อคะแนนสองเท่า: 1,000–2,000
- โบนัสตอบถูกติดกัน +100 ต่อข้อ (สูงสุด +500)
- ปรับสูตรได้ที่ฟังก์ชัน `handleAnswer` ใน `server.js`

## รันบนเครื่องตัวเอง
ต้องมี [Node.js](https://nodejs.org) เวอร์ชัน 18 ขึ้นไป

```bash
npm install
npm start
```

เปิด `http://localhost:3000/admin` → กด **▶ เริ่มเกม** ที่แบบทดสอบ → จอโฮสต์จะแสดง QR code

### เล่นในวง Wi-Fi เดียวกัน (ห้องเรียน/ออฟฟิศ)
ให้คอมที่รันเซิร์ฟเวอร์และมือถือผู้เล่นต่อ Wi-Fi เดียวกัน ระบบจะใส่ IP ในวง LAN ลงใน QR ให้อัตโนมัติ (เช่น `http://192.168.1.20:3000/play?pin=...`)
ถ้ามือถือเข้าไม่ได้ ให้อนุญาตพอร์ต 3000 ใน Firewall ของเครื่อง

## 🌐 ขึ้นเว็บออนไลน์ (Render + Neon — ฟรี)

ใช้ 3 บริการ ทั้งหมดสมัครฟรีได้: **GitHub** (เก็บโค้ด), **Neon** (ฐานข้อมูลเก็บควิซ), **Render** (รันเว็บ)

> ทำไมต้องมีฐานข้อมูล: ดิสก์ของโฮสต์ฟรีจะถูกล้างทุกครั้งที่รีสตาร์ตหรือ deploy ใหม่ ถ้าไม่ใช้ฐานข้อมูล ควิซที่สร้างไว้จะหาย

### ขั้นที่ 1 — สร้างฐานข้อมูลที่ Neon
1. สมัครที่ https://neon.tech แล้วกด **New Project** (เลือก Region เป็น Singapore จะเร็วที่สุดสำหรับไทย)
2. ในหน้า Dashboard กด **Connect** แล้วคัดลอก **Connection string** ที่ขึ้นต้นด้วย `postgresql://...` เก็บไว้
3. ไม่ต้องสร้างตาราง — แอปสร้างให้เองตอนเริ่มทำงาน พร้อมใส่ควิซตัวอย่าง 1 ชุด

### ขั้นที่ 2 — เอาโค้ดขึ้น GitHub
1. สมัคร/เข้า https://github.com แล้วกด **New repository** ตั้งชื่อ เช่น `quizblitz` (เลือก Private ได้)
2. ในหน้า repo ที่ว่างอยู่ กด **uploading an existing file** แล้วลากไฟล์และโฟลเดอร์ทั้งหมดในโปรเจกต์นี้ลงไป (ไม่ต้องมี `node_modules`) → กด **Commit changes**

ถ้าใช้ git เป็น:
```bash
git init && git add . && git commit -m "QuizBlitz"
git branch -M main
git remote add origin https://github.com/<ชื่อผู้ใช้>/quizblitz.git
git push -u origin main
```

### ขั้นที่ 3 — Deploy ที่ Render
1. สมัคร https://render.com ด้วยบัญชี GitHub
2. กด **New → Blueprint** แล้วเลือก repo `quizblitz` (Render จะอ่านไฟล์ `render.yaml` ให้อัตโนมัติ)
3. Render จะถามค่า 2 ตัว:
   - `ADMIN_PASSWORD` — รหัสผ่านสำหรับเข้าหน้าจัดการ ตั้งให้เดายาก
   - `DATABASE_URL` — วาง Connection string จาก Neon
4. กด **Apply** รอประมาณ 2–3 นาที จะได้ลิงก์เว็บ เช่น `https://quizblitz-xxxx.onrender.com`

### ขั้นที่ 4 — ใช้งาน
- ผู้ดูแล: เปิด `https://<ลิงก์ของคุณ>/admin` → ใส่รหัสผ่าน → สร้างควิซ → กด **▶ เริ่มเกม**
- ผู้เล่น: สแกน QR บนจอ หรือเข้า `https://<ลิงก์ของคุณ>` แล้วพิมพ์ PIN — ใช้เน็ตมือถือที่ไหนก็ได้
- QR จะชี้ไปที่ลิงก์ของ Render ให้อัตโนมัติ

### ข้อจำกัดของแพ็กเกจฟรีที่ควรรู้
- **Render ฟรีจะ "หลับ" ถ้าไม่มีคนใช้ ~15 นาที** การเปิดครั้งแรกหลังจากนั้นจะรอประมาณ 1 นาที
  → ก่อนเริ่มเกมจริง ให้เปิดหน้า `/admin` ทิ้งไว้สัก 1–2 นาทีก่อน ระหว่างเล่นเว็บจะไม่หลับ
  → ถ้าไม่อยากให้หลับเลย เปลี่ยนเป็นแพ็กเกจเสียเงินในหน้า Settings ของ service
- ถ้า Render รีสตาร์ตระหว่างเล่น ห้องที่เปิดค้างอยู่จะหาย (ควิซที่บันทึกไว้ไม่หาย)
- ทุกครั้งที่แก้โค้ดใน GitHub Render จะ deploy ใหม่ให้อัตโนมัติ

### ใช้โดเมนของตัวเอง
ใน Render ไปที่ service → **Settings → Custom Domains** เพิ่มโดเมน แล้วตั้งตัวแปร `PUBLIC_URL=https://quiz.โดเมนของคุณ` เพื่อให้ QR ใช้โดเมนนี้

### แพลตฟอร์มอื่น
มี `Dockerfile` ให้แล้ว ใช้กับ Railway, Fly.io, Google Cloud Run หรือ VPS ได้ — ตั้งตัวแปร `ADMIN_PASSWORD`, `DATABASE_URL` และ `PUBLIC_URL` (ถ้าแพลตฟอร์มไม่ส่ง header ชื่อโดเมนมาให้) ข้อสำคัญคือแพลตฟอร์มต้องรองรับ **WebSocket** และรันแบบ **1 instance** (เกมเก็บสถานะห้องในหน่วยความจำ) จึงใช้กับ Vercel/Netlify ไม่ได้

## ตัวแปรสภาพแวดล้อม
| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `PORT` | `3000` | พอร์ตของเซิร์ฟเวอร์ |
| `ADMIN_PASSWORD` | (ว่าง) | ตั้งไว้เพื่อบังคับใส่รหัสผ่านก่อนเข้าหน้า Admin/เปิดห้อง — **ควรตั้งเมื่อขึ้นอินเทอร์เน็ต** |
| `PUBLIC_URL` | (อัตโนมัติ) | URL หลักที่ใส่ใน QR เช่น `https://quiz.example.com` (บน Render ใช้ลิงก์ของ Render ให้เอง) |
| `DATABASE_URL` | (ว่าง) | Connection string ของ PostgreSQL — ถ้าใส่ จะเก็บควิซในฐานข้อมูล **(ควรใส่เมื่อขึ้นออนไลน์)** ถ้าไม่ใส่จะเก็บเป็นไฟล์ |
| `DATA_DIR` | `./data` | โฟลเดอร์เก็บไฟล์ `quizzes.json` (เมื่อไม่ได้ใช้ฐานข้อมูล) |
| `MAX_PLAYERS` | `300` | จำนวนผู้เล่นสูงสุดต่อห้อง |

ตัวอย่าง: `ADMIN_PASSWORD=1234 PUBLIC_URL=https://quiz.example.com npm start`
(Windows PowerShell: `$env:ADMIN_PASSWORD="1234"; npm start`)

## โครงสร้างไฟล์
```
server.js            เซิร์ฟเวอร์: REST API + Socket.IO + ลอจิกเกม/คะแนน
storage.js           ที่เก็บควิซ: PostgreSQL (DATABASE_URL) หรือไฟล์ JSON
data/sample-quizzes.json  ควิซตัวอย่างที่ใส่ให้ตอนเริ่มครั้งแรก
render.yaml          ตั้งค่าสำหรับ deploy บน Render
Dockerfile           สำหรับแพลตฟอร์มที่ใช้ Docker
public/
  index.html         หน้าแรก (ใส่ PIN)
  admin.html         หน้าจัดการแบบทดสอบ   → js/admin.js
  host.html          จอโฮสต์              → js/host.js
  play.html          หน้าผู้เล่น (มือถือ)   → js/play.js
  js/avatars.js      รายการตัวละคร/สี (ใช้ร่วมกับเซิร์ฟเวอร์)
  js/common.js       ฟังก์ชันที่ใช้ร่วมกัน
  css/style.css      สไตล์ทั้งหมด
```

## ข้อควรรู้
- ห้องเกมเก็บไว้ในหน่วยความจำ ถ้ารีสตาร์ทเซิร์ฟเวอร์ ห้องที่เล่นค้างอยู่จะหายไป (แบบทดสอบที่บันทึกไว้ไม่หาย)
- กันการเดารหัสผ่าน: ใส่รหัสผ่านผิดเกิน 10 ครั้งใน 15 นาที จาก IP เดียวกันจะถูกพักไว้ชั่วคราว
- ตรวจสถานะเซิร์ฟเวอร์ได้ที่ `/healthz`
- รันได้ 1 instance — ถ้าต้องการหลายเครื่องต้องเพิ่ม Redis adapter ของ Socket.IO และย้ายสถานะห้องไปเก็บที่ Redis
- รูปประกอบคำถามใช้เป็นลิงก์ (http/https) ยังไม่มีระบบอัปโหลดรูป
